# Changes since v1.14.2

## :warning: Information about bug fixes

Previously it has been possible to have duplicate IP address allocations if using
mixed allocations, this release fixes that. _Mixed IP allocations are not production
ready._ Mixed allocations means IP addresses allocated from the same pool for both
`ipClaim` (Metal3 CR) and `ipAddressClaim` (CAPI CR).

_If user have ended up with a duplicate IP allocation (same IP for ipClaim and
ipAddressClaim) then the user needs to manually delete one of the claims that is
deemed to the duplicate. There is no automation to recover from this._

- Fix double IP allocation and harden pivoting e2e test (#1720)
- Make IPClaim re-link check IPAddress ownership (#1711)
- Enhance IPClaim & IPAddressClaim update error management (#1707)
